# 内核地址空间与页表构建

内核已把映射策略、页表存储/遍历和 MMU 切换分开。设计参考 x-kernel 的 `mm/memspace::new_kernel_layout`、`map_linear` 和底层 `page_table::map_region`：上层描述区域，底层负责页表结构。启动时使用统一预留池，不依赖尚未初始化的堆或用户帧分配器。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `arch/kernel/boot.rs` | 建栈、清零 BSS、校验六寄存器交接、发现内核物理基址 |
| `memory/address.rs` | 带范围检查的镜像地址与物理直接映射地址换算 |
| `memory/kernel/layout.rs` | 从链接符号、交接参数和平台配置生成映射区域 |
| `memory/kernel/mod.rs` | 持有正式内核页表、组装布局、管理双别名堆保护页 |
| `arch/kernel/vspace/paging.rs` | 四级遍历、按需分配下级表、区域映射及失败回滚 |
| `arch/kernel/vspace/page_table.rs` | AArch64 页表项编码和解码 |
| `arch/machine/mmu.rs` | 发布页表、切换 TTBR、TLB 与控制寄存器操作 |

构建入口只执行三个区域集合的映射：内核镜像、物理直接映射、设备。区域携带 `VirtAddr`、`PhysAddr`、长度和 `MemFlags`；布局层没有页表层级、索引移位或物理表指针。

## 映射策略

镜像范围来自 ELF 链接符号，物理基址来自 `AT S1E1R` 查询并经启动代码校验。按 text、rodata、可写数据和栈/堆/帧池划分连续区域，text 为 RX，其余按 R/NX 或 RW/NX 映射。引导栈保护页作为区域间的空洞保留。

直接映射使用固定 VA 偏移加实际 PA。内核镜像的直接映射副本沿用相同读写权限，并全部移除执行权；保护页同样留空。内核末尾到 root image 后保留程序头页的已发现物理区间独立描述，包含 DTB 等 loader 元数据，不把它误当成内核镜像 VA 的延伸。

GICD、GICR、UART 分别按平台配置声明为 Device/RW/NX 区域。UART 始终保留，用于 LOG=off 时的内核 panic。设备跨页表边界时由通用遍历器建立下级表，不依赖 GIC 和 UART 恰好落在哪个 L2 索引。

所有正式内核映射使用 4 KiB 页，不采用早期 loader 的宽权限大页。上层拒绝低地址、未对齐或溢出的区间，物理范围不得超过平台支持的地址宽度；权限必须可读，禁止 USER、RWX 和可执行 Device。

## 地址换算与页表查询

内核链接 VA 固定，加载 PA 由 loader 选择。`arch::machine::mmu::translate_current` 使用当前硬件页表查询；启动入口在切换页表之前通过它发现 `skernel` 的实际 PA，校验后发布启动信息。后续镜像换算和正式页表构建均使用这个运行时基址，不依赖编译期加载 PA，也不修改镜像代码。

`memory::address` 接口使用 `VirtAddr` 和 `PhysAddr`，失败返回 `AddressError`：

- `kernel_image()?.to_phys(va)` / `.to_virt(pa)`：在实际内核镜像范围内双向换算，范围为半开区间，末尾地址不属于镜像。
- `phys_to_virt(pa)` / `direct_to_phys(va)`：选择或解析物理直接映射别名，检查物理地址宽度与 VA 窗口。
- `virt_to_phys(va)`：接受内核镜像或直接映射 VA；拒绝用户地址。镜像基址尚未发布时返回错误。

这些函数只计算地址，不保证页面已经映射。保护页也有可计算的 PA，但不能访问。需要确认实际映射时，调用 `memory::kernel::translate(va)` 或指定用户空间的 `AddressSpace::translate(va)`，返回包含页内偏移的 PA、页权限和页大小；未映射页面返回错误。用户空间查询不依赖当前 TTBR0，避免查询另一个任务时误用当前任务页表。两类正式页表当前均使用 4 KiB 页。

用户内存复制先校验整个范围及权限，再逐页查询目标地址空间，通过物理页的内核直接映射别名复制。页表查询不会授予访问权限，也不改变页面所有权。

## 存储和失败语义

`KernelSpace` 持有一个 `TablePool` 和两个根：TTBR1 的内核根，以及内核执行期间 TTBR0 使用的空根。统一池取代按用途预分配的 ROOT/RAM_L1/RAM_L2/RAM_L3/IMAGE_L3 等全局数组。

池的容量按固定平台 RAM 窗口保守计算，足够容纳两个 RAM 大小的 4 KiB 映射窗口和上级表、设备分支。存储在稳定的内核静态区域中，按需要分配表；未使用空间不会作为页表连接进根。它仍是有界预留资源，不是按需向堆申请内存，也不支持任意规模的平台。

每个新下级表只连接一次。遍历遇到已有表时校验物理表地址属于本池，避免解引用任意物理地址。页表操作不静默覆盖既有映射。

`map_region` 只用于尚未激活的根。遇到重叠或容量耗尽时，先移除本次已经写入的叶子，再按相反分配顺序解除新表连接，并恢复池分配位置；之前成功的区域保持有效。整个布局构建失败时不安装新根。页表在安装后保持固定地址和所有权，内核不回收其存储。

## 激活和运行期修改

完成区域映射后结束 `SingleCore` 可变借用，再调用 `arch::machine::mmu::install_kernel_roots`。保持 loader 的 MAIR 槽位，发布表项后安装 TTBR1/空 TTBR0，执行 TLB 失效并设置栈对齐与 WXN 检查。

任务内核栈的保护页操作放在 `memory/kernel`：先验证地址属于堆且页对齐，通过正式页表遍历定位镜像和直接映射的两个 L3 表项，校验两处都具有预期映射后才一起修改。设置保护只做 valid→invalid，恢复只做 invalid→valid；结束借用后执行屏障和 TLB 失效，再允许调度或释放内存。这里不分配或释放下级表，因此恢复保护页不依赖空闲页表资源。

用户页表的初始低地址层级准备函数移到 `arch/kernel/vspace/paging.rs`。用户 Frame/PageTable 对象和托管地址空间仍使用原有对象所有权及用户帧池；本次没有把内核预留池扩展为用户页表的隐式分配器。

## 验证

`kernel-test` 中的 `test/paging.rs` 对未激活根直接调用生产映射器：跨 2 MiB、1 GiB、512 GiB 边界，验证物理映射；使用只有四张表的池制造部分成功后的耗尽；检查碰撞回滚、旧权限保留、地址与权限拒绝以及容量恢复。

`make check` 同时覆盖真实硬件页表的完整映射集合、AP/PXN/UXN 和设备属性、引导保护页、运行期双别名保护页及回收、用户任务执行，以及相同内核 ELF 在不同 PA 和 root VA 下运行。可用 `make run` 启动 fatboot 装载 hello。

`test/address.rs` 验证运行时镜像基址换算、越界拒绝、页内偏移、软件与硬件翻译一致、双别名保护页、不同用户空间的同 VA 映射、跨页复制和取消映射。`check_relocation.py` 在两个实际加载位置运行这些内核测试，并核对测试内核 ELF 哈希一致。
